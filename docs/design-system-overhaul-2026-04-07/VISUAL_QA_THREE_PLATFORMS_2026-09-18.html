Verdict

The design system is specified and the shared shell is in place. It is not yet implemented consistently on all three platforms. A user switching Portal → Talent → Performance still meets three visual languages: Figma-imported Portal, mixed Talent, and token-clean Performance.

The product should feel like one internal operating system: deep teal shell, white workspace, Plus Jakarta Sans, orange for attention, green for progress, red only for harm. Current Performance follows that. Portal home and login do not. Talent is halfway.

Platform notes

Portal Largest drift

Home is still a Figma export (Frame1000001738) mounted inside the shared shell. That screen brings its own colors, type, and layout instead of PageHeader / StatCard / shared cards.

Login and the Microsoft mock also sit outside the product system: Inter, Microsoft blue, gray paper. That is acceptable as a fake Microsoft step. The Rinjani sign-in around it should still use Plus Jakarta Sans and teal primary actions.

Package-local App.tsx still composes a second Rinjani header and sidebar. The integrated host does not use that App, but the leftover chrome is a trap for future screens.

Talent Mixed

Newer HQ screens (Organization, Competency, some Job Tender admin, Talent Home) import shared PageHeader. Most journey screens still import the local shadcn Button/Card/Sheet.

When Talent is inside the host, its layout unwraps children and drops the 24px inset. Job Tender Explore uses zero horizontal padding. Career Aspiration is 16px, below the 24–32px page inset. Sheets clip footers at 100% zoom. Those defects were confirmed on 11 September and are still open.

Performance Current platform is the model

The live switcher entry is Rinjani Performance on /performance-v2. Screens use shared-ui, a page frame with 24px padding, and no raw hex. This is the visual target for the other two platforms.

The old Performance package is hidden and redirects, but it still contains a full Portal-like Figma import tree, local shell, and 46 local primitives. Do not put it back in the switcher. Treat it as dead UI, not a second design language.

Shell (shared across all three)

The integrated host owns one AppShell: teal rail, teal command bar, white rounded workspace, platform switcher, search, notifications, profile. Platform list is Portal, Rinjani Talent, Rinjani Performance. Deprecated Performance is hidden: true.

  • Pass in code: one header, one sidebar, header owns switching, Talent unwraps its nested shell when embedded.
  • Not visually confirmed in this pass: collapsed rail, active nav, workspace corner radius, notification popover, profile menu, Design System page as Admin.
  • Login is outside the shell, which is correct, but the login visual language does not match the shell.

Must fix now vs later

Now — what a reviewer will see as “not one product”

  1. Promote one PageFrame into shared-ui and put it on Portal home, Talent journey pages, and keep it on Performance. Kill zero-padding and calc(100vh-64px) routes.
  2. Harden the shared Sheet (scroll + sticky actions) and stop using the three local Sheet copies on live Talent panels.
  3. Stop shipping Figma Frames as Portal home. Rebuild the dashboard with shared Card / StatCard / Banner against tokens.
  4. Replace local Button/Tabs/PageHeader on the screens people actually click this week (Portal home, Career Aspiration, Job Tender, Talent Pool).

Later — cleanup that does not change the first impression

  1. Delete or quarantine packages/*/src/imports and unused local shadcn kits.
  2. Remove leftover Portal/Performance App.tsx shells.
  3. Map remaining hex in IDP, Analytics, and charts to semantic tokens.
  4. Remove legacy CSS aliases after copied screens are gone.
